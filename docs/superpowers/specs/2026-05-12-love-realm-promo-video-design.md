# Love Realm 项目介绍视频设计

- 日期：2026-05-12
- 项目：Love Realm
- 目标产物：一支基于 HyperFrames 制作的项目介绍视频
- 视频定位：面向玩家的混合型宣传片
- 目标时长：30-45 秒，按约 38 秒设计

## 1. 目标

这支视频不是技术演示，也不是单纯录屏。它要让第一次看到项目的玩家在很短时间内理解三件事：

1. `Love Realm` 是一个以恋爱互动叙事为核心的作品。
2. 它不是一次性对话，而是会记录关系、记忆和剧情推进的长期体验。
3. 它既有真实可玩的界面，也有可导出为小说、可作为桌面应用运行的完整产品感。

视频的主要成功标准：

- 观众能在前 8 秒内感知到“温柔、梦幻、恋爱叙事”的气质。
- 观众能在 20 秒内看懂这是一个可选择世界、进入剧情、推进关系的产品。
- 观众能在结尾记住 `Love Realm` 名称和一句核心价值表达。

## 2. 受众与表达重点

目标受众是玩家，不是开发者或投资人。因此内容优先级如下：

1. 沉浸感
2. 角色关系推进
3. 长篇互动叙事体验
4. 世界与章节分支的可持续游玩感
5. 小说导出与桌面版作为补充亮点

不强调的内容：

- 底层技术栈细节
- API 配置流程
- 数据模型或工程结构

## 3. 形式选择

采用 `混合型` 结构：

1. 用 HyperFrames 原生动效完成情绪化开场与品牌收尾。
2. 用真实项目页面作为中段展示素材，保证视频内容不空泛。
3. 用中文温柔旁白和同步字幕串联信息。

不采用纯录屏方案，原因是纯录屏难以建立宣传片质感；也不采用纯动效概念片，原因是那会削弱产品真实感。

## 4. 整体风格

### 情绪关键词

- 温柔
- 梦幻
- 亲密
- 细腻
- 安静但有余韵

### 视觉方向

整体沿用现有项目 UI 的暖色基调，并在视频中做更电影化的放大：

- 主色：米白、奶油色、浅玫瑰、棕金
- 质感：柔光、雾面玻璃、暖阴影、轻微景深感
- 动效：缓入、漂浮、柔和推拉、薄雾式转场、卡片聚焦
- 画面避免过强对比和高饱和霓虹色

### 版式方向

- 标题卡偏大字留白
- UI 展示时突出局部聚焦，不平铺全页信息
- 字幕节奏跟随旁白，不堆满屏幕

## 5. 视频结构

总时长按约 38 秒拆分。

### Scene 1：情绪开场（0-7 秒）

目标：建立气质和产品钩子。

画面内容：

- 柔和背景光晕与漂浮纹理
- 标题句逐层出现
- 品牌名暂不急着完整露出，先给一句情绪钩子

建议文案方向：

- “不是一段对话。”
- “而是一段会记住你的关系。”

旁白目标：

- 用一句话建立“关系会被记住”的核心认知

### Scene 2：世界入口（7-14 秒）

目标：让观众理解这是可进入的故事世界。

画面内容：

- 展示世界书架页
- 聚焦世界卡、角色卡、进入世界按钮
- 通过镜头推近和局部高亮体现“选择一个世界，开启一段关系”

旁白目标：

- 表达“从世界开始，不只是从聊天开始”

### Scene 3：主舞台体验（14-26 秒）

目标：展示产品核心卖点。

画面内容：

- 展示主聊天舞台
- 强调连续叙事式回复
- 聚焦关系状态、记忆摘要、建议行动
- 用局部推进镜头表现“角色会回应、关系会变化、剧情会延续”

旁白目标：

- 说明角色不是机械回复，而是会沿着记忆与关系继续靠近你

### Scene 4：补充亮点（26-33 秒）

目标：补足“长期体验”的外延能力。

画面内容：

- 快速切换幕后设定区域
- 带到角色设定、世界设定、小说导出等功能点
- 可以补一帧桌面版启动或桌面版存在感

旁白目标：

- 点出“故事可以整理成章节，也可以继续被保存”

### Scene 5：品牌收尾（33-38 秒）

目标：完成记忆点收束。

画面内容：

- 品牌名 `Love Realm`
- 一句最终收束文案
- 背景回归最简洁的柔光舞台

建议文案方向：

- “把每一次心动，写成会继续生长的故事。”

## 6. 配音与字幕

### 配音

- 语言：中文
- 声线：女声或中性偏柔和声线
- 语速：中慢速
- 表达方式：克制、亲近、不做夸张广告腔

### 字幕

- 以完整短句为主，不逐字跳动
- 每句字幕尽量控制在 8-16 个汉字的可读区间
- 字幕作为旁白同步辅助，不重复堆叠过多信息

### 旁白稿原则

- 句子短
- 不使用技术术语
- 不堆砌“沉浸式”“革命性”之类空词
- 每一句都要对应真实界面或真实能力

## 7. 素材策略

视频素材分两类：

1. `HyperFrames 原生场景`
   - 开场标题卡
   - 收尾品牌卡
   - 字幕、光效、转场、镜头强调

2. `真实项目素材`
   - 世界书架页
   - 主聊天舞台
   - 幕后设定或导出相关界面
   - 如有需要，可补桌面版启动界面或应用图标素材

界面素材应来源于本地运行的项目截图或录制，避免凭空伪造页面。

## 8. HyperFrames 制作方案

实现上采用单个主项目，内部按多场景组织。

计划内容：

- 建立一套本视频专用的视觉身份文件，明确颜色、字体和禁用项
- 用 16:9 横版作为主输出
- 场景间必须使用柔和过渡，不能硬切
- 每个场景元素都要有独立 entrance 动画
- 中段 UI 展示优先用“镜头聚焦 + 局部高亮”而不是复杂飞入飞出

建议输出规格：

- 分辨率：1920x1080
- 帧率：30fps
- 初版质量：standard
- 最终质量：high

## 9. 制作步骤

1. 启动本地项目，生成可录制的真实界面素材
2. 整理需要进入视频的页面截图或短录屏
3. 创建 HyperFrames 项目
4. 编写视频专用视觉身份文件和旁白文案
5. 搭建五段场景
6. 生成中文配音并同步字幕
7. 运行 lint / inspect / preview
8. 渲染审看版
9. 如无明显问题，输出最终版

## 10. 验证标准

成片需要满足以下标准：

- 画面风格与项目现有 UI 气质一致
- 旁白、字幕、画面之间没有信息冲突
- 在静音观看时也能看懂核心卖点
- 没有廉价模板感或与产品不一致的虚假界面
- 整体时长控制在 30-45 秒内

## 11. 风险与约束

### 风险

- 如果真实页面素材准备不足，中段会显得空
- 如果旁白过长，会压缩镜头停留时间
- 如果转场过多，会削弱温柔梦幻的气质

### 约束

- 必须围绕项目真实能力表达
- 不引入与当前产品不符的功能承诺
- 不将视频做成偏技术说明风格

## 12. 推荐的最终交付

第一版交付建议包含：

1. 一支约 38 秒的横版 MP4
2. HyperFrames 工程文件
3. 可复用的中文旁白稿
4. 若需要，再追加一个无配音字幕版

## 13. 结论

本方案的核心不是“展示一个 AI 聊天项目”，而是把 `Love Realm` 呈现成一个会记住玩家、会生长关系、会延续剧情的恋爱叙事体验。视频表达上应以温柔梦幻为主，用真实界面支撑可信度，用 HyperFrames 动效完成气质提升。
